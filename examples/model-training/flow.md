# Диаграмма процесса (Flow) тонкой настройки LLM

Ниже представлена пошаговая схема процесса (Workflow), восстановленная строго по структуре ячеек и логике выполнения вашего Jupyter-ноутбука. 

---

### 📖 Разбор терминов простым языком:
*   **Флоу (Flow / Workflow):** Последовательность шагов или конвейер (pipeline), через который проходят данные от самого начала (сырой файл) до самого конца (готовая к работе модель).
*   **Батч (Batch):** Порция данных, которая подается в видеокарту за один раз. Вместо того чтобы скармливать модели все 200 строк разом, мы делим их на группы (например, по 8 строк).
*   **Валидация (Validation):** Проверка модели на текстах, которые она **не видела** во время обучения, чтобы убедиться, что она реально научилась думать, а не просто зазубрила правильные ответы.

---

### 🗺️ Графическая схема процесса (Workflow)

```text
       [ НАЧАЛО: Сырой датасет CSV ]
                    │
                    ▼
     [ Шаг 1: Проверка ресурсов GPU ] ──► (Команда !nvidia-smi)
                    │
                    ▼
       [ Шаг 2: Импорт библиотек ] ──► (PyTorch, Transformers, PEFT, bitsandbytes)
                    │
                    ▼
   [ Шаг 3: Prompt Engineering (Шаблон) ]
                    │
                    ▼
  [ Применение метода .map() к датасету ] ──► (Обертывание строк в разметку ### Instruction)
                    │
                    ▼
   [ Шаг 4: Загрузка модели и токенизация ]
                    │
                    ├─► Скачивание весов Dolly 3B из бакета S3
                    ├─► Квантование базовой модели в формат INT8 (8-бит)
                    └─► Превращение слов в ID токенов (левосторонний паддинг)
                    │
                    ▼
      [ Очистка и разбиение данных ] ──► (Фильтрация < 256 токенов -> Train/Test split)
                    │
                    ▼
      [ Шаг 5: Конфигурация LoRA ]
                    │
                    ├─► Полная заморозка базовых весов модели (requires_grad=False)
                    └─► Создание параллельных матриц LoRA (Ранг r=256, Alpha=512)
                    │
                    ▼
         [ Настройка DataCollator ] ──► (Маскирование вопросов, лосс только по ответам)
                    │
                    ▼
      [ Запуск Trainer.train() (10 эпох) ] ──► (Обучение матриц LoRA через оптимизатор AdamW)
                    │
                    ▼
     [ Сохранение adapter_model.bin ] ──► (Финал этапа тренировки)
```

---

### ⚙️ Подробное описание каждого шага флоу:

1.  **Инспекция железа:** Первым делом флоу инициализирует команду проверки памяти. Если видеокарта занята, конвейер останавливается, заставляя пользователя освободить VRAM.
2.  **Сборка конвейера (Импорты):** Подгружаются все необходимые математические библиотеки. На этом же этапе отключается кэширование Hugging Face для экономии диска машины.
3.  **Стандартизация текста:** Сырые данные из CSV-таблицы превращаются в стандартизированные диалоги. Без этого шага модель не сможет понять, где заканчивается вопрос пользователя и где начинается её зона ответственности (ответ).
4.  **Сжатие и Векторизация:** Конвейер скачивает тяжелые веса (~7 ГБ), сжимает их «на лету» до формата INT8 (экономия памяти) и трансформирует буквы в числовые векторы. Короткие строки выравниваются по левому краю (Left padding).
5.  **Фильтрация аномалий:** Конвейер проверяет длину векторов. Всё, что длиннее 256 токенов, отбрасывается, чтобы застраховать видеокарту от случайного падения по нехватке памяти (OOM). Данные делятся на тренировочную выборку и валидационный тест.
6.  **Изоляция и внедрение LoRA:** Оригинальная модель полностью изолируется от изменений (замораживается). К ней «дописываются» легкие слои LoRA (всего 3% от общего объема параметров).
7.  **Фокусировка внимания (Коллатор):** Конвейер указывает тренеру маскировать текстовые блоки вопросов. Модель настраивает свои коэффициенты, ориентируясь исключительно на качество генерации ответов.
8.  **Итеративное обучение:** Запускается цикл оптимизации на 10 эпох. Пакеты данных (батчи) по 8 строк поочередно проходят через сеть, вычисляется ошибка, и градиенты обновляют веса LoRA.
9.  **Экспорт артефактов:** Модель возвращает управление, сохраняя на диск только обученный файл адаптера `adapter_model.bin` и настройки токенизатора, завершая тем самым весь цикл тренировки.
